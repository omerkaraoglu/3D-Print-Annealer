# Rev3.0 carrier frame v2 - verification toolchain (CadQuery)

Checks an injection-moulded PA6-GF30 carrier frame that is delivered as a **STEP file plus a parameters JSON**
(v2 is modelled in Fusion 360 by a separate workflow; its files land in `Mechanical/Rev3.0_Frame/`). Nothing is
modelled here: every check reads the frame from the STEP. The v1 toolchain (`../frame/`, CadQuery-built frame
with eight feet) is the template; its logic is copied, not imported, so this folder runs on its own.

Design documents: `Design Reports/Rev3.0/Rev3.0_Frame_Design.md` (v1). The `fusion/` subfolder,
`hole_pattern_calc.py`, `hole_pattern_result.json` and `fit_analyse.py` belong to the Fusion workflow and are not
used or changed by these scripts.

## Run

```
<venv>\Scripts\python.exe build_v2.py                 # v2: Rev3.0_Frame_v2.step + Rev3.0_Frame_v2_params.json
<venv>\Scripts\python.exe build_v2.py --v1            # regression run on the v1 frame (Rev3.0_Frame.step + v1_params.json)
```

Options: `--frame <step>`, `--params <json>`, `--board <board STEP>`, `--export-board` (run kicad-cli read-only
if no board STEP is found), `--no-render`, `--out <dir>` (JSON), `--img <dir>` (PNGs; the DXF then goes there
too unless `--dxf <path>` is given). Each module also runs alone with the same flags
(`cadcheck_v2.py`, `fitcheck_v2.py`, `calc_v2.py`, `render_v2.py`, `sections_v2.py`, `drawing_v2.py`).

Runtime on the v1 frame (342 faces, 155 board items): 286 s end to end - fitcheck 211 s, cadcheck 15 s, calc 8 s,
renders + sections + drawing 52 s. The board STEP read is ~4 s and is cached for the whole process.

## Coordinate frame

X = KiCad absolute x, Y = -(KiCad absolute y), Z = 0 at the physical PCB back, +Z = component side,
-Z = towards the oven front sheet; mould pull = Z. All plan values in the params JSON, in `board_geom.json` and
in the JSON reports are KiCad absolute (x, y down) - tagged `_abs`. The KiCad STEP export has no copper/mask,
so the board is moved by `BOARD_DZ = +0.08` (physical PCB back at Z 0; the frame-to-PCB distance reads 0.080).
Front-view drawings and the DXF use u = -(x - x_c), v = -(y - y_c) from the sheet-window centre, as v1.

## What each check means

### cadcheck_v2.py (STEP only)
- **Slivers** (owner's Battery Sentinel rule): any face with 2A/P < 0.3 mm or area < 0.5 mm2 fails. Info list:
  planar faces whose in-plane bbox minor extent is < 0.3 mm (the smallest bbox extent, the face's own thickness,
  is dropped).
- **Draft** (pull Z): every face classified; flagged = planes parallel to Z, cylinders with their axis on Z (should
  be drafted cones - holes cored by pins included), cones / other surfaces with < 0.25 deg. Flagged faces are
  identified against the stud / PCB-hole / peg tables.
- **Thin-wall probe**: plan sections at Z_FRONT + 1.25, Z -6, -3, -0.5 (+0.013 if a horizontal face lies exactly
  there), rasterised at 0.05 mm; local thickness = largest inscribed disc (morphological opening, scipy EDT) for the
  material and for the gaps. Regions thinner than 1.0 mm are listed; parallel-sided ones (fill >= 0.6) are walls /
  slots and fail, wedges are V-notches (a boss bulging out of a wall face, two rounded outlines meeting: knife-edge
  tool steel, cured by a root fillet) and are listed only. (Scan-line run lengths, as first briefed, read oblique
  chords through round holes as thin gaps; the inscribed-disc measure does not.)
- **Flange face**: all -Z faces at Z_FRONT (bbox, area); nothing below Z_FRONT except the pegs; near-coplanar
  recesses (< 0.2 mm) listed.
- **Features vs params**: stud holes, stud tubes (OD, top Z, washer bearing area = tube top face inside a dia-12
  disc), PCB pilots and bosses, pegs - found in the STEP at the params' positions.

### fitcheck_v2.py
- 3D distances and common volumes (BRepExtrema) to the 145 component models (Q1 leads trimmed to 2.5), PCB body
  (0.08 expected), panel parts, FPC tails (>= 1.5), Formex sheet, gasket, oven-sheet patch; lead protrusions vs the
  Formex sheet. Speed: a KD-tree over the frame's sampled surface gives an upper bound, then BRepExtrema runs only
  against the frame faces whose bboxes lie within it - the result is exact; beyond 5 mm the sampled value is
  reported (flag `approx`, error < 0.5 mm).
- **Tool access**: per stud a dia-12 socket cylinder from 0.5 below the stud-tube top (Z_STUD_TOP) to Z +45, centred
  on the hole / slot centre, vs every board solid (warn < 1.0 mm).
- **Washer / socket vs frame**: a dia-12 cylinder from each stud tube top to Z +45 must not touch the frame
  (DIN 9021 washer flat on the tube, nut and socket free).
- **Nothing above the PCB**: frame volume above Z 0 inside the board outline + 1 mm must be 0; also the volume
  inside the outline itself and the plan gap from frame material above Z 0 to the board edge.
- **Plan checks** (2D, from the STEP): contact patches = planar +Z faces at Z 0 (+-0.01): distance to every B.Cu
  pad polygon (>= PAD_CLR, minimum with pad name, split rib / boss / wall) and to mains copper; creepage = that
  distance + rib side + shelf back + shelf inner face + shelf/sheet interface (v1 formula, numbers from params,
  >= 6.4); clearance round the shelf corner (>= 4.0). The same on the **footprint** (frame section at
  Z_SHELF_BACK + 0.02, the rib bases incl. root fillets; v1's nominal-rib check) is reported as INFORMATION; the
  governing numbers are the Z 0 patches and the 3D distance from the frame to the component model of the nearest pad
  (leads, solder wire), which must be >= PAD_CLR.

### calc_v2.py
PCB bosses (v1), gasket force / tolerance (v1), stud-tube bearing under the DIN 9021 washer (measured area when
found), clamp margin, flange bending at the worst stud (three cases: brief lever = offset and plate = tube OD;
the same with the radial rib as a T-section; lever from the tube face with 45 deg spread; case d: strip tube-OD x
FLANGE_T + rib STUD_RIB_T x h with h MEASURED on the STEP (vertical probes along the rib centreline), lever = stud
offset, worst = max gasket + 10 g, sustained = nominal gasket + 1 g), beam lift per run
between holes along each edge with the corners as supports (analytic section wall + flange + shelf, I about the
combined centroid, v1 = 309 mm4; plus the I measured on the STEP section at each run's midpoint; full-q bound and
partial load where the glass edge runs; limit min(100 um, 0.3 x compression) at 1000 h nominal), corner
overhangs and runs walked round the corners (info), thermal mismatch frame vs steel (dT 60 K, CLTE 30 / 70 / 12
ppm/K) measured from where the frame is really held - the datum (pegs' midpoint) when both peg holes are slots
along the peg line (held across it, self-centred along it; plus a worst case with the frame offset by the studs'
across-slot clearance along that line), the round peg when only the other is a slot, the midpoint when both are
round - with the table from a declared `datum_x/datum_y` reported too if different; each stud's movement
split along / across its slot axis against (slot length - M4)/2 and (slot width - M4)/2 less the position
tolerance; peg-to-peg growth vs the peg slot play,
weight and 10 g shock. Material: PA6-GF30 FR at 110 C, tensile 75, creep allowance 15, E 3500 / 1750 MPa.

## Params JSON

Read tolerantly (`common_v2.Params`): any nesting; `{"name", "value", "unit"}` records or plain `"key": value`;
names matched ignoring case, `_`, spaces; units `mm`, `cm`, `m`, `deg`, `rad` (numbers or strings like
`"4.5 mm"`); rectangles as `[x0, x1, y0, y1]` or four scalars `NAME_X0/X1/Y0/Y1` (or `XMIN...`); point tables as
lists of `{name, x, y}` / `{name, x_abs, y_abs_down}` (or `Y_model`) or `{name: [x, y]}` (KiCad abs; an
all-negative y column is taken as model Y and flipped), or as scalar parameters `h<n>_x/_y` (PCB holes),
`peg<n>_x/_y`, `fh<n>_x/_y`; tables are also told apart by their point names (H<n>, P<n>, anything else = studs).
If a key is spelled differently, add the alias to `ADAPTER` at the top of `common_v2.py`.

Fusion v2 file (`Rev3.0_Frame_v2_params.json`): `user_parameters` list (lower-case names: `wall`, `rib`, `stud_hole`,
`stud_boss_od`, `outer_x0..y1`, `pocket_x0..y1`, `tr_x0..y1`, `panel_x0..`, `va_x0..`, `loop_z_bot/top`, `h1_x..`,
`peg1_x..`), `derived_levels_mm`, `stud_holes` (`x_abs`, `y_abs_down`, `slot_axis`, `slot_length_mm`,
`slot_width_mm`), `pegs`, `stud_hole_geometry` (`rib_per_tube` -> a radial rib of thickness `rib`),
`support_ribs.per_rib` (reach echoed into `summary.json`), `body`, `checks`. Per-side `flange_w_l/_r/_t/_b` and
`stud_offset_l/...` override `flange_w` / `stud_offset` (beam section, section dims).
**Slots**: per hole `slot_axis` ('x' / 'y' / [ux, uy] / angle) + `slot_length[_mm]` (+ `slot_width[_mm]`), else
`stud_slot` (a total length, or the elongation if smaller than the hole) along the edge. Hole centre = slot
centre: the tool and washer checks centre there, cadcheck looks for both round ends, calc checks the thermal
movement along / across the slot, the drawing shows the slot, and the sheet DXF keeps round dia-4.22 PEM holes.
**Datum / pegs / stud**: `datum_x`, `datum_y` (thermal datum, also used to spot slot axes given in model Y-up:
an axis that is radial only after flipping y is flipped, with a note); pegs: per-peg `slot_*` in the pegs table, else
with two pegs both are sheet slots along the line joining them, length = peg hole + `peg_slot` (default 0.7;
0 = round, as v1); stud part number from any string key / record named like `stud_spec` / `pem_stud`
(default "PEM FH-M4-18"; its length also sets the stud model).
**Rib reach**: the creepage path's "shelf back" term uses the rib reach measured on the STEP footprint at the
mains contact point (so extended / per-rib reach is taken from the geometry, not from `PCB_RIM_W`).
**Fillet blends**: R0.5 root fillets create sphere / torus / small B-spline corner patches below the owner's
0.5 mm2 sliver limit; cadcheck lists them by class and gives a second verdict without them.

Canonical names (first alias shown; `ADAPTER` has the rest):

| group | keys | if missing |
|---|---|---|
| frame (required) | `WALL`, `RIB_T`, `DRAFT`, `POCKET_CLR`, `SEAT_W`, `PCB_RIM_W`, `SHELF_T`, `PILOT_D`, `BOSS_OD`, `STUD_HOLE_D`, `STUD_OD`, `OUTER` (body outline at Z_FRONT, abs) | error |
| flange / studs | `FLANGE_W`, `FLANGE_T`, `FLANGE_R`, `STUD_H` (above the flange back), `STUD_OFFSET`, `STUD_RIB_T` | FLANGE_W 0, FLANGE_T = WALL, rib 0, offset from the table |
| levels | `Z_FRONT`, `Z_FLANGE_BACK`, `Z_STUD_TOP`, `Z_SHELF_BACK`, `Z_SEAT`, `Z_PANEL_BACK`, `Z_GLASS`, `Z_TROUGH_TOP`, `Z_PCB` | derived exactly as v1 `frame.py` |
| plan | `POCKET`, `TROUGH` | POCKET = PANEL +- POCKET_CLR; TROUGH optional (section / drawing dims) |
| tables | `stud_holes` (or `studs`, `stud_hole_table`, `mount_holes`, `feet`, ...), `pcb_holes`, `pegs` | studs required; PCB holes = H1..H9 default; no pegs |
| board / panel facts | `PANEL`, `VA`, `AA`, `PANEL_T`, `PANEL_T_TOL`, `STANDOFF`, `PCB_T`, `SHEET_*`, `GASKET_*`, `OVEN_SHEET_T`, `CUTOUT_*`, `SCREW_D`, `CBORE_*`, `PAD_CLR`, `LOOP_Z`, `LOOP_CLR`, `PEG_D`, `PEG_H` | v1 values (`DEFAULTS`), listed in `summary.json` -> `params.defaults_used` |

`body` (volume) and `checks` blocks of the params JSON are copied into `summary.json`; the volume is compared
with the STEP.

## Regression (`--v1`)

`build_v2.py --v1` compares with v1's `tools/frame/out/{fitcheck,calc,summary}.json` (or the embedded copy if
v1 moves) and prints every row with the reason for any difference. Known, explained differences: the Z 0
contact patches are the drafted rib tops (+0.04-0.05 vs v1's nominal rib; the footprint rows reproduce v1
exactly), the boss-to-pad minimum (v1 used the full dia-8 circle, partly buried in the wall), the longest top span
(corners count as supports: 59.6 vs 59.7) and the stud bearing (measured free ring 53.9 mm2 instead of 55.0).
